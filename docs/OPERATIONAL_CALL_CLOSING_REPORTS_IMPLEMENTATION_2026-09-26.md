# تنفيذ بيانات الاستدعاء والإغلاق التشغيلية — 2026-09-26

## النطاق المنفذ

- وقت استدعاء المجموعة لكل يوم تشغيلي ومجموعة.
- الاستدعاء الطارئ للعامل مع الوقت والسبب.
- وقت إغلاق الألعاب لمشرف تولان.
- وقت إغلاق المطاعم لمشرف الملقا.
- جميع السجلات السابقة نهائية بعد الحفظ: لا توجد API للتعديل أو الحذف.
- تسجيل العمليات في `audit_log` بالإضافة إلى حفظ صاحب السجل ووقت إنشائه في `operational_day_events`.
- تقرير أوقات الإغلاق وتقرير الاستدعاءات في `/operations/daily-reports`.
- عرض رقم العامل قبل الاسم في تفاصيل دفعة الرواتب، مع ترتيب داخل المجموعة حسب رقم العامل (ترتيب رقمي طبيعي) أو الاسم.
- عرض وقت استدعاء المجموعة والاستدعاء الطارئ في تفاصيل/طباعة دفعة الرواتب كمعلومات فقط.

## قاعدة اليوم التشغيلي

اليوم التشغيلي يبدأ 04:40 وينتهي 04:39 في اليوم الميلادي التالي. عند إدخال وقت من 00:00 إلى 04:39، يحفظ `event_at` بتاريخ اليوم الميلادي التالي مع بقاء `work_date` هو تاريخ اليوم التشغيلي المحدد.

مثال: `work_date = 2026-09-26` ووقت الإغلاق `01:30` => `event_at = 2026-09-27 01:30:00`.

## عدم التأثير المالي

السجلات الجديدة لا تنشئ حضوراً، ولا تعدل `attendance_events`، ولا `worker_daily_finance`، ولا مبالغ أو خصومات أو صافي دفعات الرواتب. الربط بالدفعة للعرض فقط.

## الصلاحيات

- مشرف تولان: استدعاء المجموعات، الاستدعاء الطارئ، إغلاق الألعاب ضمن مراكز التكلفة المسندة له.
- مشرف الملقا: استدعاء المجموعات، الاستدعاء الطارئ، إغلاق المطاعم ضمن مراكز التكلفة المسندة له.
- `restaurant_operations`: استدعاء المجموعات والاستدعاء الطارئ ضمن النطاق المسند.
- `super_admin`: صلاحية شاملة.
- `admin_affairs`: استعراض تقرير الاستدعاء والإغلاق، بدون إنشاء السجلات النهائية من واجهة التشغيل.

## قاعدة البيانات

يجب تطبيق الملف التالي يدوياً قبل تشغيل النسخة البرمجية الجديدة:

`drizzle/0026_operational_day_records.sql`

المخطط لا يشغل migration تلقائياً. الملف يوسع `operational_day_events` بإضافة أنواع الأحداث الجديدة و`event_key` و`group_id` و`event_at` وفهرس فريد يمنع تسجيل السجل النهائي نفسه مرتين.
